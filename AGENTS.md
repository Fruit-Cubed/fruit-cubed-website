# AGENTS.md

Static single-page marketing site for "Fruit Cubed" (student product-design project). Tracked in a Git repo, but the site itself is still only `index.html`, `styles.css`, `script.js`, `products.js`, `assets/`, and `fonts/` — no `package.json`, build step, tests, linter, formatter, or CI. Don't look for them or introduce one.

Except as a placeholder for images and icons, do not use emojis in sentences of prose.

## Run / verify

- Open `index.html` in a browser, or serve locally with `python3 -m http.server 8000` and visit `http://localhost:8000`.
- Verification is visual only: resize across the 850px/600px breakpoints, toggle the mobile menu, add products to the cart (the fruit flies into the cart button, the card swaps Add to Cart for a − / + stepper, the badge updates, and the drawer stays shut until you click the cart toggle), adjust/remove quantities both in the drawer and on the cards, check the total, and click Checkout (a placeholder `alert`; the button is disabled and "Clear cart" is hidden while the cart is empty). The drawer also closes from its ✕, the overlay and the Escape key.
- The absolute path contains spaces (`.../My Drive/Y10 Product Design/...`) — always quote it in shell commands.
- `.DS_Store` files are macOS/Google Drive noise, not source; leave them alone.
- `DM Sans` loads from Google Fonts (needs network); the two display fonts are local.

## Layout

- `index.html` — the entire page. Anchor targets: `#about` (on `.intro`), `#info` (on the blue `.product-information` band), `#process`, `#impact` (on the full-width coral `section.impact` band) and `#products`. The nav links to `#about`, `#info`, `#products` (twice — the second is "Shop Now") and `#impact`, while the footer links all five; so `#process` is footer-only and the rest appear in both. Section order is hero, intro, product-information, process, impact, products, footer, and each section's full-bleed background alternates (gold, cream, blue, sage, coral, cream, dark) so no two neighbours match; the sticky nav is also cream, and `body.cart-open` locks scrolling behind the drawer. The overlay (`#cartOverlay`) and `#cartDrawer` sit after `</footer>`, just before the script tags. The shop grid is an empty `<div class="product-grid"></div>`; `renderProducts()` builds every card from `PRODUCTS`. The footer ends with a `.copyright` disclaimer stating that Fruit Cubed is a student project and not a real commercial entity, and that Kapsalon Brush is used under its non-commercial demo licence.
- `products.js` — `PRODUCTS`, the catalogue: product id → `{ name, price, description, emoji, image, className }`, in card order. Loaded before `script.js` as a classic script, and the only place product names, descriptions, emoji and prices are written (the drawer's own wording lives in `script.js`). `image` is `""` on all three placeholder products, so the emoji shows until a photo path is added. A plain `.js` file rather than `.json` on purpose: `fetch` fails on `file://`, and opening `index.html` straight from disk has to keep working.
- `styles.css` — `@font-face`, `:root` tokens, then one `/* =====` … `===== */` banner block per area, then both `@media` queries at the end. Banner order follows feature areas rather than page order — the cart drawer, fly-to-cart and bump animation share the SHOPPING CART banner, and the impact banner comes last even though its section is earlier in the page.
- `script.js` — nav behaviour (`toggleMenu()`, the `.nav-links` click listener that closes the mobile menu, and `notifyComingSoon(product)`, which nothing currently calls) and the cart: `CART_STORAGE_KEY`, the `PRODUCTS` catalogue from `products.js`, a `cart` object of id → quantity filled by `loadCart()` and saved by `saveCart()`, `formatPrice()`, and `addToCart`, `changeQuantity` (a step below 1 deletes the entry), `removeFromCart`, `clearCart`, `renderProducts`, `syncProductCards`, `renderCart`, `openCart`, `closeCart`, `openCheckout` (placeholder `alert`, no payment). `renderCart()` also hides "Clear cart" and disables Checkout while the cart is empty. `flyToCart(productID, source)` throws a temporary `.fly-to-cart` chip from the clicked Add to Cart button to `.cart-icon` using `getBoundingClientRect()` and two custom properties (`--fly-x`, `--fly-y`); `bumpCart` pops the button when it lands. The cart is saved to `localStorage` under `fruitcubed.cart` on every change and restored at startup, and a `keydown` listener closes the drawer on Escape. `renderProducts()` and `renderCart()` are called once at the bottom of the file to build the page.
- `fonts/` — `Kapsalon Brush DEMO.otf` (used by `h1`/`h2`) and `FruitCubedCaligraphy-Regular.otf` (used only by `.floating-label`), wired up via `@font-face`.
- `assets/logo.svg` — the logo in the nav and footer, and the favicon; it carries its own green fill.
- `assets/shopping-cart.svg` — the nav cart icon, shown via `<img class="cart-icon">`; it is decorative (`alt=""`), so the button keeps the `aria-label`. Its `fill` is the `--dark` value copied literally, since an `<img>` can't inherit `currentColor`.

**Ignore the `Website Feedback.rtf` file**. The file is simply a place where feedback is recorded, but not necessarily immediately acted upon.

## Conventions and gotchas

- `script.js` is a classic script loaded at the end of `<body>`; `index.html` uses inline `onclick="toggleMenu()"`, `onclick="openCart()"`, `onclick="closeCart()"`, `onclick="clearCart()"` and `onclick="openCheckout()"`, and `renderProducts()`/`renderCart()` write inline `addToCart(...)` / `changeQuantity(...)` / `removeFromCart(...)` handlers, so all of these must remain global functions. Wrapping the file in an IIFE or converting it to an ES module silently breaks every button. `addToCart`'s second argument is the clicked button (`this`), used to find the card the fruit flies out of; drop it and the animation stops, while the cart still works.
- Use the `:root` tokens (`--amber-flame`, `--gold`, `--light-coral`, `--sage-green`, `--ocean-blue`, `--cream`, `--dark`, `--white`) instead of new literal hex values. Muted body text is deliberately the literal `#647368` everywhere; the pastel product tiles are literal `#ffe9a4` / `#f7d0cd` / `#c7e1bb`, the disabled checkout and footer muted text use `#c5d0c8`, and the footer rule is `#506156` — those are not tokens by design.
- Grids (`.info-grid`, `.steps`, `.product-grid`) are 3 columns, drop to 2 at 850px and 1 at 600px; the hero also stacks at 850px. The menu toggle only exists below 600px, where `.nav-links` is `display: none` until it gains `.active`; `toggleMenu()` also keeps `aria-expanded` on `.menu-toggle` in sync. Above 600px the toggle is hidden and the links are always visible.
- The cart toggle lives in `.nav-actions` beside the menu toggle and is visible at every width; its `.cart-count` badge is hidden (`.empty`) while the cart is empty and shows the total item count otherwise. `.cart-item-image.strawberry|.mango|.citrus` reuse the pastel card colors. `openCart()` is called only by that toggle and also shuts the mobile menu; `closeCart()` runs from the drawer's ✕, the overlay and the Escape key, and both keep `aria-expanded` on `.cart-toggle` in sync and toggle `body.cart-open`. Adding to cart updates the badge and the total but deliberately leaves the drawer shut — don't "fix" it by calling `openCart()` from `addToCart()`.
- Each shop card carries both an Add to Cart `.product-button` and a `.product-quantity` stepper (− count +); `syncProductCards()` toggles their `hidden` attributes from `cart[id]`, so a product shows the stepper only while it has at least one in the cart. It is called at the end of `renderProducts()` and `renderCart()`, which keeps the cards in step with changes made in the drawer or by Clear cart. `changeQuantity(productID, change, source)` takes the clicked button as an optional third argument so the card's + flies the fruit like Add to Cart does; the drawer's own − and + pass two arguments and stay silent. Because `addToCart()` calls `flyToCart()` before `renderCart()`, the clicked Add to Cart button is still visible when its position is measured — swap the two and the fruit launches from the page's top-left corner.
- Header hover is movement, not colour: `.nav-links a`, `.nav-button`, `.menu-toggle` and `.cart-toggle` all lift `translateY(-2px)` on hover with `transition: 0.3s`. `.nav-links a` is what gives both the plain links and `.nav-button` that transition, and the links are flex items, which is why `transform` works without an explicit `display`. Don't reintroduce colour changes on nav hover.
- The shop card is data: `renderProducts()` writes the emoji (or `image`, when set), `<h3>`, description, price and the `onclick` product ids from `PRODUCTS`, while the labels themselves (Add to Cart, −, +) are fixed in its template. Editing, renaming, adding or removing a product is a `products.js`-only change — never hard-code a card back into `index.html`. `notifyComingSoon(product)` is still global and ready for a "coming soon" trigger, but nothing calls it at the moment.
- The cart persists across refreshes in `localStorage` (`fruitcubed.cart`, a JSON map of product id → quantity). `loadCart()` re-validates every saved entry against `PRODUCTS`, so a renamed or removed product is dropped instead of crashing `renderCart()`; both read and write are wrapped in `try`/`catch` because storage can be blocked (private mode) or full. The "Clear cart" button is hidden (`.cart-clear[hidden]`) and Checkout is `disabled` while the cart is empty, both set at the end of `renderCart()`; `clearCart()` asks for a native `confirm()` before emptying it and `openCheckout()` refuses an empty cart, matching the placeholder `alert()` style.
- The add-to-cart animation is CSS-driven: `@keyframes fly-to-cart` in `styles.css` reads `--fly-x`/`--fly-y`, which `flyToCart()` sets inline per flight. It launches from the button that was clicked (not the card image) so a card scrolled partly off screen can't start the flight from off view; the chip still borrows the card image's computed `background` for its colour only. The path is two-legged: across to a point 46px straight above `.cart-icon`, then down into it, over 0.55s — the 46px lift (60% keyframe) and the per-keyframe easing that makes the drop accelerate are both CSS-only, so retiming or re-pathing needs no JS change. `flyToCart()` bails out when the visitor prefers reduced motion (`matchMedia("(prefers-reduced-motion: reduce)")` in JS — there is no CSS media query for it). The chip's `animationend` removes it and pops `.cart-toggle` via `.bumped` (`cart-bump`, 0.45s); that listener fires on the flight's own duration, so keep the two durations in sync.
- Font filenames contain a space and are referenced verbatim in `@font-face` (`url('fonts/Kapsalon Brush DEMO.otf')`); keep the names and the space as-is.
- Match existing formatting: 4-space indent (the second `@font-face` block uses tabs — leave it), blank lines between rules, multi-line `/* ===== */` banner comments per area. No formatter is configured, so hand-match.
- If `styles.css` has selectors with no matching markup (`.product-link` today), don't delete them as dead code or assume HTML was lost.
- The project is tracked in Git, but do not run `git commit`, `git push`, `git reset`, `git rebase`, or any other git mutation unless the user explicitly asks for it. Confirm first each time.
